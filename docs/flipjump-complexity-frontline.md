# Complexity front line: stl-additions / stl-seq-ptr

Existing stl macros whose own cost changed on these branches, or whose documented complexity was already wrong.
Macros affected only through a call to one of these (add_constant, ptr_inc, mul10, div, the pointer *_and_inc
ops, ...) are not listed. Their docs are unchanged on both branches (the round-1 lines were reverted in 60ccaef
and 0aa69ca); this table proposes the new lines.

Measured by `scratchpad/stlx/measure_doc_w.py`: time = executed ops per call, space = image ops per call (every
segment, the wflip area included), each as (K = 8 calls - no calls) / 8 in one program; n = 1, 2, 4, 8, 16 (t = time,
s = space). @ = log2 of the program's image ops (it grows with n in the bigger macros). At a second program size
(the calls behind a 174,762-op filler, @~17.5) the times scale as the @ terms predict; the json files hold both.
Space shows no @ term: the wflip chains are shared, and placed in the pads. The stl-seq-ptr rows are measured on
stl-seq-ptr (0aa69ca); "before" is eacc7ee. w(0.25@+3) is the arm (set_flip_and_jump_pointers) as measured here.
