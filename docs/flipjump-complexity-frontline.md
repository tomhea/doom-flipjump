# Complexity front line: stl-additions (rev 4, 2026-10-24)

Baseline = **origin/main**'s lines (the owner reviews 1.6.0 -> main). Rows: (A) the existing macros whose own code changed on stl-additions, or whose line was wrong by the conventions below; (B) the one-shadow rows: every macro whose line changed between main and eacc7ee (1.6.0, 232f737 and siblings). Section 7 lists the transitive dependents whose lines were re-derived; all these lines are APPLIED on stl-additions (section 8).

## 1. The conventions (one rule)

- **@** = log2 of the program's ops; a code address has about @/2 on-bits.
- **Every executed wflip costs the on-bits of its VALUE**, in time and space: a general address @/2, a pad-2^k label @/2 - k/2 (pad 16: @/2-2, pad 4: @/2-1), a chained step's xor **2** (measured, section 2), a constant or an init label its own popcount (hex.mul.init's after_add: 2, at op 2304 in every program; hex.pointers.to_flip: 3; dbit+8: 5).
- **Callees compose at their documented cost** (hex.xor @ / @+12, xor_zero @+4 / @+28, zero, if @-1 / @+15, the tables), EXCEPT the classic lines that charge constant-valued wflips at @/2, which are re-derived and become front-line rows: read_*_from_inners_ptrs (5@+13 -> 3@+40) and the mul flow (@+24 -> 32).
- **Worst cases stay worst cases**: hex.mul's `if n` and div/idiv's compares and subtracts keep the classic worst case.
- **Space never counts shared chain tails** (the assembler shares a tail between wflips with one return address); the emitted space is reported as a lower bound, the no-sharing count from the op stream is what the lines count.
- **Pads are not counted** (filled with wflip chains: get_wflip_spot takes pad slots first). The classic lines never counted them (hex.xor's @+12; or.init's 595 leaves out its pad 256).
- **No "~". One significance rule (owner)**: a term without the line's size parameter (a pure constant, or a w term) is dropped when it is <= 15% of the line's value at size 16 (w = 64, @ = 18.5), and kept above. Size parameters (n, d (digits), b (non-zero hexes, mul), f (fraction hexes), nb, src_n, dst_n, n_const, m-j, idx_n, sw, h, bits, len, count) are never dropped. Fixed-size lines (no size parameter: ptr_inc, read_hex, ptr_index dst, ptr, index, read_nth / write_nth, ...) keep every term, as main's own lines do (main keeps read_hex's 7@+13 next to w(0.75@+5)). The n-cell ops arm once, so their w term is outside n: kept when > 15% (read_hex n 30%, write_hex n 18%), dropped in write_byte n (12.7%).

## 3. The arm (set_flip_and_jump_pointers), derived and checked at two addresses

Per pass and pointer hex h: 2 pad-16 wflips (@-4) + the src op + the k-group table's entries (k * popcount(h), or 1 for h = 0); main runs 3 passes (k = 2, 2, 4), 1.6.0 two (k = 3). `arm_check.py`: time - wflip popcount == the predicted plain ops EXACTLY, at both @ (18.45, 20.43):

| stl | pointer | wflips | plain ops (measured = predicted) |
|---|---|---|---|
| main | 0x80 | 96: w(0.75@-3) | 100.5 |
| main | 0x7fffffffffffff80 | 96 | 450.5 |
| 1.6.0 | 0x80 | 64: w(0.5@-2) | 67.5 |
| 1.6.0 | 0x7fffffffffffff80 | 64 | 331.75 |

So the w term's @ part is exact (0.75@ on main, 0.5@ on 1.6.0: 0.25@ an address bit a pass), and its constant depends on the pointer: w(0.5@-1) for 0, up to w(0.5@+4.5) for all-f hexes; the lines keep the documented w(0.5@+4), the dense case. The n-cell lines have NO n*w term: part C arms once (w(0.5@+4) outside n) and each cell only advances (2@+6, no w).
